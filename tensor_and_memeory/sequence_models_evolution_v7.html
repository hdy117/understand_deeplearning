序列模型的记忆：从 RNN 到 Hybrid DeltaNet

同一道「记账题」贯穿七代模型 · 少压缩、多搭桥 · 给视觉学习者的一版

嗨，我是 Ember。这篇不是「术语速通」，而是把序列模型当成一本会更新的账本来讲：它怎么写、怎么读、为什么会串味、为什么有时改不了口。

0. 先把题目出出来

0.1 一道题，四条验收

先把「语言」这层皮剥掉。驱动架构演化的，经常不是「语义有多深」，而是一件更无聊、更硬的事：记账准不准。

t = 1     write (A, 1)
t = 2     write (B, 5)
t = 3     write (A, 3)     ← A changed its mind
t = 4..91 eighty-eight distractors
t = 92    query: what is A? what is B?
correct:  A = 3, B = 5

文献里这类任务叫 associative recall。它不考语法，不考常识，只考：你的状态里有没有一本不乱的簿子。

把这道题拆成四条验收标准——后面全文只用这四个词，好记：

标记要求一句话检验怎么记
留住长记性：旧记录别被时间冲掉第 1 步写的，第 92 步还在留得住才叫记忆
改口可覆盖：同一 key 写新值，读出来是新的A 改成 3 后，读到 3，不是 1 和 3 的混合物能改口，不是只会追加
隔离不串扰：改 A 不动 B改 A 时，B 仍是 5各记各的，互不串味
定容状态大小与序列长度无关N 从 4K 到 128K，状态形状不变定住容量，不随 N 膨胀

定容说的是「状态大小」，不是「时间」。串行带来的延迟往往比状态膨胀更早杀死一个架构——这一点后面账单里会反复出现。

flowchart LR A[Write A=1] --> B[Write B=5] B --> C[Rewrite A=3] C --> D[88 distractors] D --> Q{Query A and B} Q -->|pass| OK[A=3, B=5] Q -->|fail| BAD[mixed / lost / crosstalk]

0.2 唯一的骨架：write / read

不管外面叫 RNN、Attention 还是 DeltaNet，一步序列计算都可以压成一对动作：

$$ S_t = \mathrm{write}(S_{t-1}, x_t), \qquad o_t = \mathrm{read}(S_t, q_t) $$
符号含义
$S_t$写完第 $t$ 步之后的全部记忆（形状决定流派）
$x_t$当前输入 token
$k_t, v_t$用来写账本的地址与内容（由 $x_t$ 投影）
$q_t$用来读账本的提问（由 $x_t$ 另一组投影）
$o_t$读出的结果，交给下一层

$k_t$ 和 $q_t$ 是同一个 token 的两个不同投影：一份拿去写，一份拿去查。这就是 Q/K/V 三件套的由来——不是神秘仪式，是「写地址」和「读问题」需要两套坐标系。

flowchart TB xt[x_t] --> write write --> St[state S_t] St --> read qt[q_t] --> read read --> ot[o_t] St -.->|carry to next step| write

后面七章改的几乎全是 write 框和 $S$ 的形状；read 那半条变动小得多。所以你可以带着一个心智模型往下走：

序列模型 = 一台状态机 + 一条写规则 + 一条读规则。

0.3 全篇唯一值得亲手推的一步

标准 attention 的加权和，可以换成「先合成矩阵、再乘 query」：

$$ o = \sum_i (q^\top k_i)\, v_i = \Big(\sum_i v_i k_i^\top\Big) q = S q $$

左边是「每个 key 打一次分，再加权 value」；右边是「先把所有 $v k^\top$ 累成一张表 $S$，query 来了只做一次矩阵乘」。形状对得上：$v_i k_i^\top$ 是 $[d_v, d_k]$，乘上 $[d_k]$ 得到 $[d_v]$。

这一步交换是整条演化史能存在的原因：从「每次读都扫全表」变成「边写边维护一张表」。没有它，后面所有 $O(N)$ 的线性注意力家族都无从谈起。

方向约定（全文唯一，后面不再改）：

  • $S \in \mathbb{R}^{d_v \times d_k}$：行 = value 通道，列 = key 方向
  • 写入：$S \leftarrow S + v_t k_t^\top$（代码：outer(v, k)）
  • 读取：$o_t = S_t q_t$（代码：S @ q）
  • $q_t, k_t, v_t$ 是单步向量$[d_k]/[d_v]$，不是整段序列的 $[n,d]$ 矩阵；把 $n$ 个向量叠起来才会出现 $Q,K,V$ 矩阵形式

有的资料写成 $S=\sum k v^\top$ 再配 $q^\top S$，与本文互为转置、数学等价。混着读会以为作者换了模型——其实只是换了纸的朝向。本文选「value 在左、key 在右」，是为了和 DeltaNet 的代码与梯度形式一致。

约定 A（本文） vs 约定 B（常见）
$S: d_v\times d_k$，写 $v k^\top$，读 $Sq$　｜　$S: d_k\times d_v$，写 $k v^\top$，读 $q^\top S$

0.4 四种记账方式（全文路线图）

骨架问题问到底——「新记录怎么并进记忆？」——答案空间很小：要么不合并，要么压进固定大小矩阵。压缩的笔法本质上三种：累加、纠错、衰减+纠错。

方式直觉更新式满足牺牲代表
不合并 账本越写越长，读时现场比分 只追加 留住·改口·隔离 定容（$O(N^2)$） Transformer
累加 每条盖一层地毯，旧的不擦 $S\leftarrow S+vk^\top$ 定容·留住 改口·隔离 Linear Attention
纠错 先读旧答案，只写差额 $S\leftarrow S+\beta(v-Sk)k^\top$ 定容·留住·改口 隔离（部分） DeltaNet
衰减+纠错 先按行过期，再纠错 先 $\gamma\odot S$，再纠错 定容·留住·改口 隔离尾巴·误伤 Gated DeltaNet

推进主线可以记成一句话：

先拿回定容（累加）→ 再拿回改口（纠错）→ 再处理过期与隔离（衰减 / Hybrid）。

RNN / LSTM 为什么不在表里？ 它们没有 $k$，也就没有「往哪个地址写」。写入是整份状态被稠密矩阵搅拌后灌回去——不是「压得不够狠」，是「没有页码」。第 1、2 章专门解剖这种无地址失败。

flowchart LR RNN[RNN no address] --> LSTM[LSTM highway] LSTM --> TF[Transformer no merge] TF --> LA[Linear Attention add] LA --> DN[DeltaNet correct] DN --> GDN[Gated DeltaNet decay] GDN --> HY[Hybrid layered]

0.5 「忘」不是独立旋钮

常有人把模型拆成「怎么存、怎么读、怎么忘」三件套。读起来整齐，但埋了个陷阱：

忘从来不是独立旋钮，它是写规则的副产品。

直觉：记忆只有一份。想让旧内容活，就得写的时候少动它；想让它消失，还是得写的时候多动它。你无法「精确只改 A，又顺便单独抹掉 B」，除非写规则里本来就带着动 B 的动作。

四种笔法里的「忘」：

  • 不合并：行还在；「忘」只是读时权重变小。真腾地方靠截断/滑窗，是工程策略，不是写规则内部旋钮。
  • 累加：没有擦，只有叠。要压旧信息只能整体乘 <1，A 和 B 一起淡——分不清该忘谁。
  • 纠错：沿 $k$ 方向覆盖，像局部用橡皮；正交方向几乎不动。能改口，但不会按时间过期。
  • 衰减+纠错：$\gamma$ 最像「忘的旋钮」，但它仍是写步骤里的乘法，作用在整行上，不是点名删除第 $i$ 条。学歪了会误伤。

所以：先谈写，再谈忘。后面 §6 的 $\gamma$，是把「写的时候顺便乘一个小于 1 的系数」显式参数化，不是天上掉下来的遗忘开关。

1. RNN：一页没有页码的账本

无地址定长向量状态

1.1 一句话 + 一个式子

RNN 每一步都在做同一件事：把旧状态和当前输入搅在一起，搅出新状态。

$$ h_t = \tanh\big(W_x x_t + W_h h_{t-1} + b\big) $$

对照骨架：$S_t$ 就是 $h_t$，整份记忆只有一个 $[d]$ 向量。所有历史都得挤进同一条窄带。$W_x$ 是新输入入口，$W_h$ 是旧状态通道，$\tanh$ 把值压回 $(-1,1)$。

渊源：固定窗口 MLP 把「能看多远」写成超参数 $k$；RNN 用递推向量承接任意长度——壮举与病根同时诞生。

flowchart LR h0[h_{t-1}] --> mix[W_h and W_x mix] xt[x_t] --> mix mix --> tanh --> ht[h_t]

1.2 同一道题怎么算（示意）

假设二维状态，A 走第 1 维，B 走第 2 维（现实中 $W_h$ 会把维搅乱，这里只为看清失败模式）：

t=1  write A=1  →  h ≈ [1, 0]
t=2  write B=5  →  h ≈ [0.5, 5]     # A already decayed by W_h / tanh
t=3  rewrite A=3 → h ≈ [3.25, 2.5]  # old A residue + B collateral damage
t=92 query       → neither A nor B is clean

两个数字全错，而且错法相反：A 是「新旧叠在一起」，B 是「被顺手砍了一刀」——分别对上改口失败和隔离失败。

1.3 机制：连「记得久」也做不到

反传时，对 $h_{t-k}$ 的梯度要穿过一长串：

$$ \frac{\partial h_t}{\partial h_{t-k}} = \prod_{j=0}^{k-1} \mathrm{diag}(1-\tanh^2(a_{t-j}))\, W_h $$

每一步乘一次 $W_h$ 和一次 $\tanh'$。$|W_h|$ 的特征值稍离 1，连乘就指数爆炸或消失；$\tanh'$ 在饱和区接近 0，再补一刀。所以留住也经常靠运气。

用矩阵语言说「没有地址」：$W_h h_{t-1}$ 意味着旧状态每个坐标都按 $W_h$ 的列配方被重新混一遍——mixing 是稠密的，没有任何一列能被单独豁免。翻译成人话：你改某一条记录时，不可避免地碰所有坐标。

1.4 类比

传话游戏常被用来类比 RNN，但失败原因常被说错。真正的问题不只是「每传一次丢一点」，而是每次传话都会把上一句和这一句搅拌成一句新的——你没有「只改第 3 个词、其他原样」的手术刀。

本章小结：RNN 四条验收基本全挂——无地址写入导致改口与隔离同时失败，梯度连乘威胁留住，唯一勉强的是状态定容（一个向量）。下一章 LSTM 只打算先还「留住」这笔债。

2. LSTM：一条直通线，三道闸门

cell highway仍无 key 地址

2.1 一句话 + 一个式子

$$ c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t, \qquad h_t = o_t \odot \tanh(c_t) $$

$c_t$ 是 cell state：一条尽量少非线性的「高速公路」。$f_t, i_t, o_t$ 是遗忘门、输入门、输出门，逐元素控制「旧的留多少、新的进多少、对外读多少」。

思想：不让信息「被传递时反复变换」，让它「自己走过去」。梯度沿 $c$ 走时主要乘门值：

$$ \frac{\partial c_t}{\partial c_{t-k}} = \prod_{i=t-k+1}^{t} \mathrm{diag}(f_i) $$

若 $f\approx 1$，乘积接近 1，长程梯度能活——这是 LSTM 相对 RNN 的真正杀手锏。

flowchart TB cprev[c_{t-1}] --> fgate[f_t forget] fgate --> add xt[x_t, h_{t-1}] --> igate[i_t and candidate] igate --> add add --> cnew[c_t] cnew --> ogate[o_t and tanh] ogate --> h[h_t]

2.2 同一道题

理想门控下：写 A 时只开 A 相关维；写 B 时只开 B 维；改 A 时对 A 维 $f\to 0$（清旧）、$i\to 1$（写新），B 维 $f\to 1$（原样保留）。看起来改口和隔离都有救。

但现实是：门是学出来的，没有显式 key 告诉它「这是地址 A」。维与符号的对齐全靠训练撞大运。短合成任务可以学得很好；开放端语言里，地址对齐并不免费。

2.3 账单：串行

LSTM 修了「留得住」的梯度路径，但每一步仍依赖上一步的 $c_{t-1}$——训练与推理都是时间串行。状态虽定容，时间成本随 N 线性涨，且难以像 attention 那样整段并行。

本章小结：LSTM 用 highway 部分赎回留住；门提供了弱形式的改口/隔离，但无显式地址。定容仍在，串行账单留给后人。下一章 Transformer 选择另一极端：拒绝合并。

3. Transformer：拒绝合并

不合并精确但昂贵

3.1 一句话 + 一个式子

$$ o_t = \sum_{i\le t} \frac{\exp(q_t^\top k_i/\sqrt{d_k})}{\sum_{j\le t}\exp(q_t^\top k_j/\sqrt{d_k})}\, v_i $$

$S_t$ 在这里不是固定矩阵，而是一张越写越长的表 $(k_1,v_1),\ldots,(k_t,v_t)$。每条记录原样躺着；$q_t$ 来了再现场打分、归一化、加权求和。

思想：合并会丢信息，那就不合并。用空间和计算换留住·改口·隔离。

flowchart LR table[(KV table grows with N)] --> scores[scores q vs all k] scores --> sm[softmax] sm --> mix[weighted sum of v] mix --> o[o_t]

3.2 同一道题

写 (A,1)、(B,5)、(A,3) 后，表里三条记录都在。问 A 时，与两条 A 的 key 都可能高分，但若位置/内容编码让「最近的 A=3」胜出，读数就是 3；B 的行原封不动。三条验收里的前三条可以同时满足——代价是表长度 = N。

3.3 为什么是 softmax

softmax 做两件事：（1）把打分变成正权重并归一化；（2）制造「赢者多吃」的竞争。没有归一化，量纲乱飘；没有竞争，改口时新旧 key 容易平分秋色，读成混合物。

它也埋下伏笔：softmax 让 $\sum_i f(q,k_i)v_i$ 不能随便把求和交换进与 $q$ 无关的括号里——结合律在这里断了。这是下一章 Linear Attention 要拆的墙。

3.4 并行与 mask

训练时整段序列可并行算 attention（配 causal mask 防止看到未来）。这是对 LSTM 串行的正面反击。推理时则用 KV cache 避免重复算历史——账单变成「每层存 $2N d$ 的 K/V」，长上下文下显存与带宽压力巨大。

本章小结：Transformer 用「不合并」买下留住·改口·隔离，卖掉定容与 $O(N^2)$。下一章问：能不能在近似意义下合并，把定容赎回？

4. Linear Attention：把求和挪到 query 前面

累加笔法定容赎回

4.1 卡点与破法

softmax 卡在结合律上。若把相似度换成特征映射的内积：

$$ \exp\Big(\frac{q^\top k}{\sqrt{d_k}}\Big) \approx \phi(q)^\top \phi(k), \qquad \phi:\mathbb{R}^{d_k}\to\mathbb{R}^{d_\phi} $$

则

$$ o \approx \frac{\sum_i v_i\,(\phi(k_i)^\top \phi(q))}{\sum_i \phi(k_i)^\top \phi(q)} = \frac{S\,\phi(q)}{z^\top \phi(q)} $$

其中递推：

$$ S_t = S_{t-1} + v_t \phi(k_t)^\top, \qquad z_t = z_{t-1} + \phi(k_t) $$

读变成 $O(d_v d_\phi)$，与 N 无关——定容回来了。它在形式上就是一个 RNN，而且对 $S$ 线性，可以用 parallel scan 加速。

flowchart TB subgraph write [write] vt[v_t] --> outer[outer with phi k_t] kt[phi k_t] --> outer outer --> addS[S += ...] kt --> addz[z += phi k] end subgraph read [read] S --> mul[S * phi q] z --> den[z · phi q] mul --> out[o = num / den] den --> out end addS --> S

4.2 同一道题：为什么改口失败

After A=1, B=5, A=3 with overlapping keys:
S holds (v_A1 + v_A3) mixed on similar key directions
query A → reads a blend, e.g. 2 instead of 3

累加笔法不区分新值和旧值：同一方向写两次就是相加。所以改口挂掉。若两条 key 不正交，外积还会在共享行列上互相加强度——隔离也挂。

上界直觉：一张 $d_v\times d_\phi$ 的矩阵，线性可区分的方向大约只有 $d_\phi$ 量级。地址需求超过这个数，必然撞车。

本章小结：Linear Attention 赎回定容与可 scan 的并行，但累加笔法先天不会改口，隔离也不稳。下一章把「加」改成「先读再写差额」。

5. DeltaNet：写之前先读一眼

纠错笔法delta rule

5.1 一句话 + 一个式子

$$ \hat{v}_t = S_{t-1} k_t, \quad e_t = v_t - \hat{v}_t, \quad S_t = S_{t-1} + \beta_t e_t k_t^\top $$

人话：先问账本「$k_t$ 上现在写着什么」，只把差额写回去。已经记住的，$e=0$，不再浪费容量。

渊源：这是经典 delta rule / online least squares 的一步。目标：

$$ \mathcal{L}_t(S)=\tfrac12\|S k_t - v_t\|_2^2 \quad\Rightarrow\quad \nabla_S\mathcal{L}_t=(S k_t-v_t)k_t^\top $$ $$ S_t = S_{t-1} - \beta_t \nabla_S\mathcal{L}_t = S_{t-1} + \beta_t (v_t - S_{t-1}k_t)k_t^\top $$

展开成「先擦后写」：

$$ S_t = S_{t-1}(I - \beta_t k_t k_t^\top) + \beta_t v_t k_t^\top $$

几何意义：沿 $k_t$ 方向把旧内容压扁，再写入新值。对 $k_t$ 精确命中时 $S_t k_t = v_t$；对正交方向 $k_\perp$，状态不变。

flowchart TB S0[S_{t-1}] --> pred[pred = S k_t] vt[v_t] --> err[e = v - pred] pred --> err err --> outer[beta * outer e k] S0 --> erase[erase along k] outer --> S1[S_t] erase --> S1 qt[q_t] --> read[o = S q] S1 --> read

5.2 同一道题

t=1 A=1  → S maps k_A → 1
t=2 B=5  → S maps k_B → 5  (if orthogonal, A untouched)
t=3 A=3  → pred≈1, e≈2, write correction → S maps k_A → 3
query A → 3 ✓   query B → 5 ✓ (when keys well separated)

改口结构性回来了。隔离在 key 近似正交时接近满分；有夹角时仍有泄漏——所以说「治了八成」。

5.3 三个漏

  1. 永不遗忘：没有衰减项，过期信息一直占着方向。
  2. 隔离不完美：非正交 key 的投影互相碰到。
  3. 并行变难：系数 $I-\beta kk^\top$ 依赖数据，不能像纯累加那样简单 scan；需要 chunk / WY 表示等更重的技巧。
本章小结：DeltaNet 用 delta rule 赎回改口；定容与大致留住仍在；隔离部分改善。账单是：更难并行 + 不会过期。下一章给每一行加半衰期。

6. Gated DeltaNet：给每一行一个半衰期

衰减+纠错per-row γ

6.1 一句话 + 一个式子

$$ S_t = D_t\big[S_{t-1} - \beta_t \hat{v}_t k_t^\top\big] + \beta_t v_t k_t^\top, \quad D_t=\mathrm{diag}(\gamma_t),\quad \gamma_t=\sigma(W_\gamma x_t+b_\gamma)\in(0,1)^{d_v} $$

三个动作按顺序：① 沿 $k$ 擦掉旧预测（DeltaNet）；② 逐行乘 $\gamma$（Mamba 风格衰减）；③ 写入新值。新写入通常不乘 $\gamma$——刚写的不该立刻过期。

pred = S @ k_t
old  = S - beta * outer(pred, k_t)
S    = gamma[:, None] * old + beta * outer(v_t, k_t)
flowchart LR S[S_{t-1}] --> erase[erase along k] erase --> decay[row-wise * gamma] decay --> write[add beta * v k^T] write --> S2[S_t]

6.2 为什么门是「逐行」的

$S$ 的每一行对应一个 value 通道。逐行 $\gamma$ 的意思是：不同特征通道可以有不同半衰期——有的信息保质期短（代词指代），有的该长留（人名、标题）。这比「整个矩阵乘同一个标量」细，又比「给每一个历史位置单独门」便宜。

6.3 同一道题与三种故障

理想：改 A 时擦 A、写 3；B 行 $\gamma\approx 1$ 不被误伤。长程 distractor 上，对噪声行 $\gamma<1$，让垃圾慢慢退场。

三种典型故障：

  • $\gamma$ 全局偏小 → 误伤，该留的也淡（伤留住）
  • $\gamma$ 学不动、常年≈1 → 退回「永不遗忘」的 DeltaNet
  • 擦与门顺序/括号搞错 → 新写也被衰减，或旧脏数据没擦干净
本章小结：Gated DeltaNet 在定容·留住·改口之上补了「过期」通道；隔离仍有尾巴，门可能误伤。压缩派的上限大致到此。若还要任意位置精确逐字召回，需要分层——下一章 Hybrid。

7. Hybrid：两种记忆分层共存

分层调度写在架构里

7.1 思想

固定大小的 $S$ 最多能干净回答约 $d_\phi$ 个独立方向；「把第 3 页第 7 行编号精确抄出来」需要任意位置的副本。这两件事在同一层互斥。

解法：不要让一层做所有事。

  • memory layers（线性 / Delta 家族）：定容，负责大意、长程背景、廉价传信息
  • retrieval layers（softmax attention）：不合并，负责精确原文、改口敏感的绑定

调度表写死在架构里：哪些层用哪种写规则，是设计选择，不是运行时搜索。

flowchart TB x[token stream] --> M[memory layers fixed-state write] x --> R[retrieval layers full KV] M --> mix[interleave / residual stack] R --> mix mix --> out[output]

7.2 同一道题

A/B 的精确绑定可以由某几层 attention 保管；88 个 distractor 的「过场」由 memory 层廉价消化。读 A=3、B=5 时，数字可能来自不同层的协作——脚注是：精确层负责改口与逐字，memory 层负责把长噪声流压住。

7.3 账单

不是「数量级魔法」，而是比例题。设 $L_m$ 层 memory、$L_a$ 层 attention：

$$ \text{train FLOPs} \approx L_m O(N d^2) + L_a O(N^2 d), \quad \text{state} \approx L_m O(d^2) + L_a O(N d) $$

多几层 attention，显存与算力立刻往 Transformer 侧滑；全用 memory，精确召回又不够。工程上常见的是小比例 retrieval 层插在深层。

本章小结：Hybrid 承认单层写规则无法同时白拿四条验收，把冲突上交到「层分工」。判断题变成：你的任务更缺精确绑定，还是更缺长上下文定容？

8. 收束：同一台状态机，七个读数

模型写规则留住改口隔离定容关键代价
RNN稠密搅拌弱无无是梯度消失/爆炸
LSTM门控 highway较强弱/靠学弱/靠学是串行
Transformer不合并强强强否$O(N^2)$ + KV cache
Linear Attn累加中无弱是混叠、容量上界
DeltaNet纠错中强强中是难并行、不遗忘
Gated Delta衰减+纠错中强强中是门误伤
Hybrid分层调度强*强*强*混合比例与系统设计

*Hybrid 的「强」来自层协作，不是单层写规则同时满分。

迁移检查（合上书之前）

  1. 给定一条写规则，你能不能预测它在留住·改口·隔离·定容上的得分？
  2. 看到 $S\leftarrow S+vk^\top$ 与 $S\leftarrow S+\beta(v-Sk)k^\top$，你能不能说出差在「有没有先读」？
  3. 有人说「再加一个遗忘门就搞定」，你能不能回答：忘是写的副产品，门乘在哪、乘在什么方向，决定误伤还是过期？
  4. 为什么 Hybrid 不是「更花的 DeltaNet」，而是承认单层冲突后的架构级分工？
最后一根钉子：能不能改口，取决于有没有地址；会不会串味，取决于写规则是不是一次投影；能不能逐字找回，取决于你留没留 $N$ 份副本。三件事各有价，没有一个架构能同时白拿。
